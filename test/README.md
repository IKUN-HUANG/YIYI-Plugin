# 单元测试

基于 Node 内置测试器（`node:test`，零第三方测试框架）。运行：`npm test` 或
`node --test "test/*.test.mjs"`（Node 24 不再接受目录参数，须用引号包住的 glob）。

## 目录结构（按模块分层，一层就到文件，不铺大目录）

```
test/
├── README.md                  # 本文件：怎么跑、写到哪、守什么
├── Harness.mjs                # 测试公用件：路径常量、读文件、动态载入插件模块、造消息事件
├── King.test.mjs              # 王者：素材目录划分、熟练度/称号映射、常用英雄表头与熟练度格
├── Memes.test.mjs             # 表情包：别家指令不被抢、功能开关是热的、兜底规则排最后
├── Utils.test.mjs             # utils：文本缓存、内存缓存、图片下载超时
└── Lint.mjs                   # 源码体检（可单独执行，也可进 CI）
```

## 约定

1. **只用 Node 自带件**：`node:test` / `node:assert` / `node:fs` / `node:os` / `node:path`。
   插件运行时依赖（`sharp`、`mediabunny`）不进测试，引入即说明用例写错了层次。
2. **不联网、不碰真数据**：测试里的输入全部由用例自己造（或读插件自带的
   `resources/`、`config/default_config/` 这类发布产物）；不读宿主 `data/`、不发请求、
   不读真实 QQ / token 形态的字符串。
3. **不改插件、不写仓库**：需要落文件的用例写 `os.tmpdir()` 并在 `finally` 里删掉；
   测试对插件源码只读，跑完工作区必须和跑之前一模一样。
4. **一层目录**：用例直接放 `test/` 下，按模块命名 `<模块>.test.mjs`；公用逻辑只放
   `Harness.mjs`，不再拆 `helpers/`、`fixtures/` 这类中间层。
5. **动态载入**：插件模块用 `Harness.load('models/…/X.js')` 按路径异步导入，
   这样不依赖 `#yiyi.*` 别名，也不受宿主是否安装影响。
6. **断言写契约**：素材在不在、映射函数输出什么、模板与样式是否还留着关键结构。
   像素级排版不进单元测试（那是出图预览的活）。
7. **邮件只用两个固定标题**：收工发「完成通知」，要人拍板发「提问」。标题一字不改，
   同类邮件在 QQ 邮箱里才会并进一个会话；测试产物与结论走正文，不拼进标题。
8. **改插件就跟着改这里**：增删导出、改默认值、换素材目录或模板名，
   `node --test "test/*.test.mjs"` 必须全绿；`test/Lint.mjs` 另外保证
   「没有 `console.*`、没有空 `catch`、没有未使用的具名导入」。
